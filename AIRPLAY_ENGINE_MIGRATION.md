# Real AirPlay mirroring: replace the incomplete RTSP/media engine

## Recommended upstream

**jqssun/android-airplay-server** — https://github.com/jqssun/android-airplay-server

Its current README (checked Nov 2026) documents an Android 7+ receiver using C-based **UxPlay** through JNI, including H.264/H.265 MediaCodec video, audio, RTSP/RAOP, FairPlay interoperability for supported non-DRM mirroring, and mDNS. Its source is **GPL-3.0**, and it has a CMake native build requiring submodules. Do not assume it is drop-in compatible with CarCastMirror: test with the specific iPhone + car LCD first.

Alternative upstream protocol source: https://github.com/FDH2/UxPlay

## Recommended engineering order

1. **Prove the backend independently**. Build/install the Android AirPlay receiver from upstream on the same Samsung Android phone or car LCD, and verify screen mirroring from the same iPhone. This isolates device, Wi-Fi, and iOS compatibility from CarCastMirror's UI. If it fails, collect upstream logs before changing CarCastMirror.
2. **Preserve GPL obligations**. If you redistribute a binary containing GPL-covered UxPlay code, comply with source-sharing, attribution and build notices. Review any applicable Apple protocol/IP restrictions separately.
3. **Integrate a native receiver into CarCastMirror**. Prefer porting the tested upstream native UxPlay/JNI backend and MediaCodec bridge to the CarCastMirror app (or port the CarCastMirror UI and Android Cast feature into the upstream Android project). Do not run the existing Kotlin AirPlayRtspServer on ports 5000/7000 at the same time as the native engine.
4. **Use one mDNS advertiser.** Keep TXT records, advertised IP and port numbers consistent with whichever backend is actually listening, and do not advertise codecs/features that are not supported.
5. **Wire JNI events to the UI/service**. Only set STREAMING after video session negotiation and first decoded frame, not merely `RECORD` or `pair-verify`.
6. **Handle video properly**. AirPlay mirrored-video transport may be separate from legacy RTP/UDP. The backend must handle real setup negotiation, framing, key handling, timing, H.264/H.265 parameter sets, and send complete decoded/encoded samples to MediaCodec.
7. **Audio separately**. Match AAC-ELD/AAC-LC/ALAC formats to the appropriate decoder; raw compressed frames are not interchangeable with PCM AudioTrack samples.
8. **Test end-to-end** on the target Android car LCD and current iOS version: Wi-Fi discovery -> connect -> live screen -> audio -> disconnect/reconnect -> landscape.

## Why the Kotlin mock engine was not sufficient

The incoming `POST /fp-setup` on port 5000 and the immediate EOF were real observations. The old server answered with `FPLY` plus mostly zero bytes, not a verified FairPlay exchange; even if the client continued, `SETUP` was a hardcoded RTP response and its receiver assumed video was plaintext H.264 inside UDP RTP. Those cannot produce working AirPlay screen mirroring.

**No native library, FairPlay implementation, or verified iPhone test has been silently included in this patch.** The honest next step is integration of the tested native receiver, not one more mock response.

## Migration Completed — Status Update

1. **Upstream Receiver Cloned & Analyzed**: `jqssun/android-airplay-server` was cloned with recursive submodules (UxPlay, ffmpeg, libplist, openssl-cmake). Baseline official release APK (`upstream-airplay-receiver.apk`) provided for isolated baseline verification.
2. **Native Libraries Bundled**: Multi-architecture native libraries (`libairplay_native.so`, `libc++_shared.so`, `libcrypto.so`, `liboboe.so`) integrated into `app/src/main/jniLibs/` for `arm64-v8a`, `armeabi-v7a`, and `x86_64`.
3. **Competing Kotlin Servers Replaced**: Incomplete `AirPlayRtspServer` (ports 5000/7000) and JmDNS advertiser removed from runtime broadcast. Single native UxPlay server listens on port 7000.
4. **Android OS DNS-SD Discovery**: `NsdServiceManager` publishes official `_airplay._tcp` and `_raop._tcp` services using native TXT records generated by UxPlay.
5. **Video Pipeline**: MediaCodec decoding with `DecoderSelector` (AVC/HEVC ladder), OpenGL ES 2.0 SurfaceTexture blitter (`VideoPipeline`), and presentation-time scheduling in `VideoRenderer`.
6. **Audio Pipeline**: Real-time decoding and playback through Google Oboe engine (`AudioRenderer`).
7. **Full Feature Preservation**: CarCast's automotive UI, reverse touch control, and Android Cast (port 8080 WebSocket + port 8088 HTTP portal) remain completely intact.
8. **GPL-3.0 Compliance**: License and project credits included.
9. **Build & Tests**: Unit tests pass (`BUILD SUCCESSFUL`), and test APK (`CarCastMirror-native-debug.apk`) successfully assembled.
